先看我们搭到了哪里

现在有了一套能实际执行的阶段化工作流：委员会推理和采样、候选选择、VASP 输入生成、收敛标签收集，以及多种子训练任务准备。每个阶段都有独立目录，可以查看结果后继续下一步。

它还不是一套已完成科学验证的“自动训练气体势”。当前 S/M/L 是预训练模型组成的诊断委员会；DFT 方法尚未选定，也没有用新的 VASP 标签训练气体模型。RuNNer 已接入官方 4G 示例进行推理验证，气体模型仍需要自己的参考数据。

一轮工作怎样流动

假设我们已经有一个能粗略描述 CO₂ 的势。先让它带着分子运动，在途中请多个模型同时判断每个构型的力。如果模型之间意见分歧大，就把这个构型留下。VASP 只对选出的少量构型计算参考能量和力，随后这些新数据进入下一轮训练。

这里的“主动”体现在选择下一批参考计算对象。采样轨迹主要由机器学习势推进，通常不需要每一步都运行 DFT。被选中的构型交给 VASP 时采用固定原子位置的单点计算：它给出此刻的能量和力，不执行 AIMD，也不先把构型优化到最低能结构。

Slurm 是计算资源的调度器，负责把采样、标注和训练任务送到计算节点。它不决定哪些结构值得标注，也不判断模型是否可靠；这些判断由工作流和验证数据承担。

委员会到底在比较什么

把同一构型交给三个模型，就会得到三组原子力。若三个成员对某个原子的预测差别大，这个局部环境值得进一步检查。委员会的平均力可以用于推进 MD；成员之间的离散程度则是候选选择信号。这两个用途必须区分。

F̄i = (1/M) ∑m Fi(m)
σi = √[(1/M) ∑m ‖Fi(m) − F̄i‖²]
构型分数：σmax = maxi σi

M 是成员数，i 是原子编号。每个力有 x、y、z 三个分量，上式先求向量差的平方，再对成员平均、开平方。因此 σ 的单位仍然是 eV/Å。代码采用总体方差，分母是 M。直接使用“方差”会得到力的平方单位，不能与这里的阈值混用。

动手看：意见一致，也可能一起错

这是一个虚构的单原子、单方向例子。其余两个方向设为零，用来解释概念；不代表任何实测气体数据。

同一份训练数据可能让三个模型共同遗漏某类物理。它们对该构型意见一致，分歧仍会很小，真实误差却可能很大。因此必须拿一批独立 DFT 标签检查“分歧增大是否伴随力误差增大”，再选择适合该体系的筛选阈值。

本次的 S/M/L 分别表示模型容量不同，不代表三个独立随机种子训练的模型。它们可以用于诊断，但共享训练来源。正式训练入口会为多个种子准备独立成员；不同种子仍不自动保证误差校准成立。

为什么纯气体还要看“分子合力”？

一个 N₂ 单体的两个原子就可能有明显的模型力分歧，来源是成员对分子内键的预测不同。把两分子相隔很远，分歧也不一定消失。若关心分子间平动作用，可以先把同一分子的原子力相加，再比较成员间的分子合力。本项目保留原子力分歧作为通用筛选指标；分子合力、转矩和分子内力需要结合分析，不能互相完全替代。

为什么不用不同模型的原始总能量直接比较？

不同势的原子参考能、训练计算方法和能量零点可能不同。二聚体相互作用能应在每个成员内部计算 Epair − Emonomer A − Emonomer B，并说明单体几何及边界条件。减去能量零点也不能消除不同 DFT 方法造成的物理差异。

RuNNer 与 MACE-POLAR 各负责什么

RuNNer 是训练和运行 HDNNP 的软件。它支持不同代际的模型；“用了 RuNNer”并不等于“用了 4G”。MACE-POLAR 则是一种具体模型架构。本仓库通过统一的 ASE 接口使用两者，它们读取的模型文件和内部计算流程依然不同。

比较项RuNNer 4GMACE-POLAR
局部环境表示原子中心描述符，例如 symmetry functions；结合原子神经网络MACE 的等变多体表示及局部网络
非局部响应网络给出电负性等参数，通过全体系 QEq 分配电荷局部表示与全局静电场耦合，通过有限次学习更新得到响应
全局计算的理解固定几何、给定网络输出后，标准二次 QEq 对电荷形成受约束线性方程组模型中的学习更新含非线性；不能等同于把标准线性 QEq 解得更精确
模型加载input.nn、缩放参数、权重目录；加载 libRuNNer.soPyTorch .model checkpoint；model_type="PolarMACE"
委员会同一原生委员会共享部分描述符等计算当前接口依次求各成员的能量和力，再计算均值与分歧
本仓库训练入口2G 能量/力训练任务；4G 训练须补充电荷标签和分阶段流程官方 CLI 的多种子训练/微调任务准备；尚未进行真实 DFT 微调

QEq 可用下面的简式理解。给定原子位置，网络提供 χ，矩阵 A 包括硬度与电荷相互作用；总电荷约束是 ∑qi = Q。

E(q) = χᵀq + ½ qᵀAq，　∑i qi = Q
Aq + χ + λ1 = 0，　1ᵀq = Q

这里“线性”指固定构型下求 q 的方程，并不表示整个势能对原子坐标是线性的。χ 和 A 随构型改变，局部网络本身也含非线性。MACE-POLAR 的有限次全局更新同样不应写成“每一步都收敛一个 SCF 循环”。两者的速度需要在相同体系、硬件、精度、线程数和计算范围下测量，不能只凭“第几代”判断。

为什么放在同一个项目？共享结构、DFT 标签、来源划分和性能统计方式，便于分别训练和比较。RuNNer 本身不会直接读取 MACE-POLAR 权重；统一的是工作流接口。

先运行一次采样

先选一个很小的 CO₂ 周期盒检查流程，不要立刻提交长轨迹。本仓库的 gas_inputs.extxyz 包含 CO₂、CH₄、N₂ 的单体、二聚体和四分子盒。下面的索引 5 是四个 CO₂ 分子的周期盒，共 12 个原子；它是手工初态，尚未经过平衡采样。

  1. 检查模型配置

    local/polar.json 指定 S/M/L 三个 checkpoint、CPU、float64、温度、时间步和候选预算。示例阈值只是流程参数，尚未用 DFT 校准。

  2. 提交 Slurm 小任务

    sbatch scripts/smoke_polar.slurm

    脚本用委员会平均力运行短程 Langevin MD，再做预热后的独立计时。示例作业按 job ID 建目录，重复提交不会覆盖上一轮结果。

  3. 查看阶段结果

    .venv/bin/python scripts/run_cli.py status runs/polar_smoke_JOB_ID

    trajectory.extxyz 保存被记录的帧，summary.json 给出完成步数、分歧、温度和停止原因，candidates.extxyz 是下一阶段输入。若没有满足条件的候选，该文件不会生成。

  4. 必要时重新选择候选

    .venv/bin/python scripts/run_cli.py select \
  --input runs/polar_smoke_JOB_ID/trajectory.extxyz \
  --minimum 0.02 --maximum 0.20 --budget 6 --min-step-gap 10 \
  --out runs/selection_round_001

    按分歧排序后，程序去除完全重复的几何，并限制同一轨迹中入选帧的时间距离。这只是初步去冗余，不等于已经覆盖所有分子取向、温度和密度。

分歧超过 stop_sigma_eVA 时，程序保存当前帧并停止继续探索。若该帧又超过候选筛选上限，它会留在轨迹中，但不会自动进入候选文件。高分歧构型可能是有价值的新环境，也可能已经出现不合理的原子重叠，需要检查。

把候选交给 VASP，而不是交给 AIMD

这一阶段的目标是得到候选构型本身的参考答案。固定原子位置，VASP 收敛电子结构后输出能量与力。若先做结构优化，得到的标签就对应优化后的几何，不能直接贴回原来的候选帧。

仓库提供 PBE-D3(BJ) 的输入格式示例，它尚未被选定为正式参考方案，也没有做截断能、真空层、k 点和色散方案的收敛检查。实际选型还应考虑需要复现的物性和 MACE-POLAR 预训练参考方法；换 DFT 方法后的训练属于适配新的能量面。

# 生成独立单点目录；会从本机 VASP_PP_PATH 读取 POTCAR
.venv/bin/python scripts/run_cli.py prepare-vasp \
  --input runs/selection_round_001/candidates.extxyz \
  --reference configs/reference_pbe_d3.example.json \
  --out runs/labels_round_001

# 参考设置确定并检查输入后，按需提交实际计算

# 计算完成后收集标签；尚未完成、失败、未收敛的任务会被列入 rejected

  --tasks runs/labels_round_001 --out runs/dataset_round_001

若只想先检查任务生成，可把上面的输入改成 examples/initial_candidates.extxyz：它是事先准备的六个种子候选，与刚产生的 MD 候选不是同一批。

每个任务都保存原始结构和 VASP 实际使用的结构。孤立分子在 VASP 中仍通过有真空的周期超胞近似；周期气体盒则保留原来的晶胞。程序记录元素排序映射，收集时把原子力恢复到原始顺序，并检查结构、参考方法和输入文件摘要是否一致。

标签采用 VASP 的力一致 free_energy 约定，写入 REF_energy 与 REF_forces。这不表示电子展宽、有限盒尺寸的影响已经可以忽略：这些误差仍需通过参考计算收敛测试控制。当前自动标注入口支持中性单重态、无外电场的气体构型，其他电子态需要扩展并验证设置。

训练与下一轮委员会

训练前，先划分数据。连续 MD 帧彼此很像，随机逐帧切分容易让训练集和验证集包含同一段运动的近邻构型，从而得到过于乐观的误差。本项目按 group 划分来源；同一组不会跨越两侧，跨组出现完全相同的几何也会被拒绝。

缺少来源标记时，标注阶段把整个输入文件保守地视为同一组，不把每帧伪装成独立样本。因此只有一条轨迹的数据不足以直接生成这里的训练/验证划分，需要更多独立来源，或明确制定有物理依据的分组策略。

RuNNer 的 2G 和 4G 训练为什么要区别处理？

2G 可以从能量和力训练局部势，本项目提供转换为 input.data 的入口，ASE 负责从 eV、Å 转到 RuNNer 的 Hartree、Bohr。示例对称函数和网络规模仅用于设置演示，不是已经优化的气体模型。

原始 4G 流程先用参考原子电荷训练电负性/硬度与 QEq，再训练短程能量部分。原子电荷依赖所选分区方法，不能把缺失电荷填零，也不能把 VASP 的任意电荷输出当成可互换的标签。各原子电荷还应与体系总电荷一致。当前训练入口会明确拒绝未经配置的 3G/4G 模板；官方 4G 推理已经接通，4G 气体训练的电荷标签和两阶段流程仍需补齐。

E0s=average 是什么意思？

它从训练数据估计元素能量基线，便于拟合能量的平移。若只有固定化学计量的分子，元素基线可能不能唯一确定；不能把拟合值解释为独立原子的物理能量。比较不同组成、反应或解离时，需要更完整的数据与一致的参考方案。

验证分成两层：软件是否按约定运行，以及模型是否适合研究对象。前者可以用受控测试检查；后者必须依赖独立参考计算和物理性质验证。下面是本次搭建实际得到的证据。

这里一次 call 指完整委员会的一次能量/力调用，后端可能同时计算应力；不含模型加载、MD 积分与文件写入。先预热 2 次，再测 5 次，取中位数，并显式调用计算器绕过 ASE 的不变构型缓存。

独立小测试体系与成员数中位计时
MACE-POLAR / CPU 4 线程 / float64CO₂ 周期盒，12 原子，3 个成员约 158,032 us/atom/step
RuNNer 4G / CPU 4 线程孤立 Ag₃，3 原子，2 个成员约 246 us/atom/step

这两行不能计算为“谁快多少倍”。元素、周期边界、原子数、成员数、模型规模与参考数据都不同。它们目前只证明计时接口可用；公平比较需要同一批构型、相近目标误差及一致计算范围。

出错以后如何继续

每次计算写入新目录，失败证据也保留。训练和标注有独占执行记录，避免重复提交在同一目录中交叉写入。这里的“续跑”指从已经完成的阶段继续，或者给失败计算建立新的尝试目录；当前没有实现 MD 的随机数与积分器状态精确重启，也没有自动重启训练 checkpoint。

看到什么意味着什么下一步
Slurm PENDING尚未获得资源，不是模型卡住用 squeue 看等待原因。
force_pbc_evaluator 接口报错旧 MACE 与静电库 API 不匹配使用记录的 graph_longrange 0.4.0 配对；不要直接丢弃边界条件参数。
stop_sigma 触发构型分歧超过探索上限检查保存帧的结构与力，再决定是否标注；不要盲目抬高阈值。
collection.json 有 rejected标签缺失、未收敛或结构/方法不匹配按任务原因处理，新尝试使用新目录。
提示仅一个 group 或重复几何当前划分不能保证基本独立性补充独立轨迹，去重或合并真实来源组。
execution_claim.json 已存在这个计算目录已经被启动过保留输出，新建尝试目录；不覆盖原始结果。

失败后重新生成任务，例如：

.venv/bin/python scripts/run_cli.py prepare-vasp \
  --input runs/selection_round_001/candidates.extxyz \
  --reference configs/reference_pbe_d3.example.json \
  --out runs/labels_round_001_retry_01

.venv/bin/python scripts/run_cli.py status runs/train_round_001/seed_17
cat runs/train_round_001/seed_17/driver.err

训练重试同样重新执行 prepare-train 并指定新的 --out。不要直接复制旧的 Slurm 脚本提交，因为其中嵌入了原计算目录的绝对路径。status 只查看指定目录；父目录有任务清单时，还要逐个查看子任务。

查看代码时，rnal/common.py 定义分歧与来源划分，backends.py 连接模型，sampling.py 负责采样与计时，labeling.py 连接 VASP，training.py 准备训练任务，jobs.py 保护任务执行。小型测试位于 tests/。

从框架走到可靠的纯气体模型

下一步应先明确具体气体、温度与密度范围，以及是否只研究非反应过程。低密度气体需要覆盖分子间取向和近碰撞；密度增加后，多分子环境和极化响应的重要性会变化。因此不能用“几个单分子算得准”替代整个研究范围的验证。

随后确定参考 DFT 方案，先做小批量标签。用它们检验单体形变、二聚体作用曲线、短程排斥和力误差，再决定如何微调、怎样补样本。委员会筛选应保留一定的随机或分层抽样作为补充，防止模型共同自信时漏掉问题；当前实现的候选选择尚未加入该补充策略。

若最终目标是复现 PRL 的 pair-correlation matching 路线，需要区分两层数据：一层用于训练微观势的能量/力参考数据，另一层是用经过验证的微观势在平衡态采样得到的 g(r)、密度以及自由能/化学势相关约束。短程接口测试和少量 DFT 标签都不能直接替代后者。
